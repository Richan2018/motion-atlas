# Motion Archive · UI 与动效精选

公开的静态设计参考资料库，包含 UI 设计、UI 动效、趣味交互、AI 产品宣传和 AI 制作动画。

## GitHub Pages 部署

本仓库根目录直接提供网页，无需 npm、构建依赖或服务器。GitHub Pages 选择发布分支的 `/ (root)` 目录即可。`.nojekyll` 保持原始静态文件发布。所有应用资源使用相对路径，可用于用户主页或项目子路径。

## 更新资料

`source-data.json` 是维护数据，`data.json` 是网页读取的数据。两者只含公开精选，无账号资料或私人对话。

1. 获取本仓库最新版本。
2. 按既有 schema 幂等追加日期和案例，保留历史内容、作者、原链接、作品日期、热度观察日及观看限制。
3. 同一原作不能跨模块重复计数；不要为达到配额编造内容。
4. 检查两个 JSON 文件可解析且内容一致，运行 `node --check app.js`，并按下方步骤完成浏览器回归。
5. 提交数据变更后核验 Pages 发布成功，以及线上日期、总量、筛选和全文。

目前归档：2026-10-26 至 2026-11-09，共 15 天、326 个案例。历史不足新配额不补造。首次迁移时仅将一处历史交付流程说明改为“已核对历史归档，避免重复收录”，所有案例正文、原链接、热度、观看限制保留。

## 网页更新与回归

- `data.json` 和 `covers.json` 使用 `cache: 'no-cache'` 重新校验，避免直接复用浏览器中仍在有效期内的旧资料。
- 返回页面、从浏览器历史恢复或恢复联网时检查更新，最多每 60 秒发起一次；页面持续可见时每 5 分钟检查。隐藏页面不轮询，同一时间只运行一组请求，15 秒超时后可重试。
- 后台请求失败或数据格式不完整时保留当前资料；内容未改变时不重绘。更新不会写入收藏、清除筛选或关闭正在阅读的全文。
- 发布脚本修改时同步更新 `index.html` 的 `app.js?v=...` 版本参数。已打开的旧版页面需要重新加载后才会运行新脚本；不需要清除浏览器存储。

应用仍无构建依赖。可在仓库根目录运行 `python3 -m http.server 8000`，打开 `http://localhost:8000/tests/refresh.html`。测试在隔离的内存收藏存储中验证日期、模块、搜索、排序、全文、原链接、收藏、新数据、重复事件、请求竞态、超时及失败恢复，不修改当前浏览器的真实收藏。预期显示 `6 passed, 0 failed`。
